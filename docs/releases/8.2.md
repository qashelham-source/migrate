# Release 8.2 — Pipeline Optimization

Release 8.2 improves pipeline responsiveness during Telegram throttling.

## Changes

- FloodWait cooldowns are isolated by operation (`upload`, `download`, `read`, `verify`, `copy`, `resolve`).
- A throttled upload no longer freezes unrelated reads, verification, dialog resolution, or downloads.
- Top-level uploads remain serialized to avoid `SaveBigFilePart` retry storms.
- Limiter telemetry now reports event count, cumulative wait time, per-operation cooldown, and per-operation totals.
- Existing configuration remains compatible; no database migration is required.

## Safety

Album uploads remain atomic at the uploader layer. This release does not increase Pyrogram's internal transmission concurrency and does not alter destination message ordering.
